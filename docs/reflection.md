# MySchedule 课程学习心得与反馈

## 1. 项目式学习收获

通过实现 `myschedule`，我们把课堂中分散学习的知识点串成了一个完整项目。相比单独练习语法或算法，这种项目式练习更能帮助我们理解“需求 -> 设计 -> 实现 -> 文档”的完整开发流程。

## 2. C++ 文件读写、类、容器和多线程

### 文件读写

本项目中账户和任务都保存到本地文件中，因此对 `fstream` 的使用变得非常具体。我们需要考虑文件初始化、文本格式设计、程序重启后的重新加载、保存失败提示和原有数据保留。

### 类与模块化

项目拆成 `UserManager`、`TaskManager`、`Storage`、`Reminder`、`AudioAlert`、`CLI`、`App` 和 Qt `CoreAdapter` 后，代码职责更清晰。各模块分别负责账号、任务、存储、提醒、音频、命令行和图形界面，定位和调整都更方便。

### 容器

`std::vector<Task>` 适合当前规模的任务列表，结合排序、筛选、遍历，可以自然地完成显示全部任务、按天过滤、按月过滤、删除指定任务等操作。

### 多线程

提醒线程是本项目中最有代表性的并发场景。通过这部分实现，我们进一步掌握了 `std::thread`、`std::atomic<bool>`、`std::mutex` 和线程退出时的 `join`。这部分也让我们更理解线程安全与实际数据结构、文件保存和用户输入之间的关系。

## 3. CMake、Qt 与语音服务

顶层 CMake 工程负责构建 C++17 命令行程序并链接线程库，`Frontend/` 中的独立 CMake 工程负责 Qt5 Widgets 界面。Qt 界面通过 `CoreAdapter` 复用核心模块，账号、任务、ID、时间和提醒规则保持统一。

语音功能让我们理解了 C++/Qt 与 Python 服务之间的边界：Qt 负责录音、上传、用户确认和表单回填；本地 FastAPI 服务负责 Whisper STT 和 DeepSeek 字段解析；Core 负责最终的任务规则校验和保存。

## 4. 命令行程序开发

命令行程序虽然界面简单，但输入输出设计同样重要。为了让程序可用，需要认真考虑参数格式、错误提示、帮助信息、表格输出和交互模式中的提醒处理。

`--help`、示例命令和交互式 `run` 让 CLI 更接近真实工具，也让核心业务逻辑可以在图形界面之外独立使用。

## 5. Git 与协作

项目按阶段完成，Git 对模块整合和修改追踪很重要。它的价值主要体现在保留开发过程、便于分阶段回看修改、保留功能分支合并记录，以及展示项目从 CLI 到 Qt、音频提醒、语音助手的演进过程。

这次实践也让我们意识到，接口约定越清晰，后续模块组合和功能扩展就越顺畅。

## 6. 解决问题的过程

数据格式方面，我们统一采用固定分隔符格式，并加入 `next_id` 元数据，让任务 ID 的分配和持久化更清晰。

时间处理方面，我们通过统一的时间工具模块集中解析和校验时间字符串，减少重复代码。

提醒线程方面，我们把任务管理层的并发访问集中到同一 `TaskManager` 实例内处理，让 CLI 主线程和提醒线程可以共享数据。

Qt 集成方面，我们通过 `CoreAdapter` 让图形界面调用 Core，界面负责展示和输入转换，核心规则保持统一。

语音功能方面，我们把麦克风、本地 Python 服务、Whisper 模型和 DeepSeek API 放在 Qt 语音入口与服务边界内，解析结果继续经过 C++ 校验后进入任务表单。

## 7. 课程建议

- 更好地结合AI发展 更新大作业要求
- 课程可以配合更多“从需求到实现”的示例，帮助大家理解较完整的软件开发过程。
- 工程结构、文档写作和 Git 协作可以作为编程实践课程中的重要组成部分。

## 8. 总结

这次项目让我们对 C++ 的理解从“会写代码”进一步推进到“能完成一个可运行、可维护、可提交的程序”。文件持久化、模块划分、参数解析、线程同步、Qt 界面和本地语音服务这些内容，比单纯刷题更能体现编程实践能力。
